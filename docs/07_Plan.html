01

Executive summary

Huuk is not missing features. It is missing a path to real use: a production-like rehearsal, working backups, a real client, a live domain and a first invoice. This plan breaks the remaining work into 8 milestones (M0–M7). Each has tickable checkpoints and a single pass/fail gate backed by evidence.

04

Milestones

M0Freeze & Green Baseline1–2 days
Goal

Lock the app/ + server/ layout and get everything green before deploying.

Checkpoints
  • Commit the folder move; update paths in DEPLOYMENT.md, dev.sh, deploy.sh, CI
  • No duplicate package-lock.json / pnpm-lock.yaml; bun install --frozen-lockfile passes
  • cargo test (94) and vitest (188) pass; fix README counts (16/17)
  • cargo build --release and bun run build pass
  • CI green on main
  • .gitignore covers data/, backups/, .env*, target/, dist/
  • cargo audit + frontend audit: fix or document high-severity findings
  • Secret scan of repo and git history (e.g. gitleaks): no leaked keys
Gate: main green; fresh clone runs bun run dev on :8787 and :5173; scans have no blockers.
Evidence: CI link, test logs, audit/scan output, tag v0.9.0.
M1Staging Rehearsal2–3 days
Goal

Run the production stack on a separate staging host with TLS and monitoring; prove rollback.

Checkpoints
  • Choose deploy path (A systemd recommended)
  • ./deploy.sh init: ADMIN_EMAIL, ADMIN_TOKEN (≥16), AUTH_REQUIRED=true, DEMO_MODE empty, ALLOW_REGISTRATION=false
  • TLS on staging (Caddy / Let's Encrypt), served over HTTPS
  • /api/health and /api/ready respond correctly
  • ./deploy.sh smoke <url> owner <password> --write passes all 7 checks
  • Verify security headers, HSTS, CSP and secure cookies over real HTTPS
  • Uptime check, log rotation and error log in place
  • Manual: publish → open /#/read/{slug} in a private window; restart keeps data; 11 wrong passwords → 429
  • Rehearse rollback to the previous version
  • Rotate bootstrap password and ADMIN_TOKEN after smoke
Gate: smoke passes over HTTPS; data survives restart; rollback works; a test alert fires.
Evidence: smoke output, HTTPS URL, /#/read screenshot, alert test.
M2Backup & Restore1–2 days
Goal

Daily encrypted off-host backups that can really be restored. Must pass before the pilot, because one snapshot is all the data (accounts, sessions, articles).

Checkpoints
  • Write down RPO ≤ 24h and RTO ≤ 1h
  • Daily systemd timer (or cron) with an alert on failure
  • Backups stored off-host and encrypted (they contain password hashes and sessions)
  • Encryption key stored separately from the backups
  • Retention (default 14) works
  • Snapshot is atomic even while the live store is being written
  • Restore rehearsal on another machine using the separate key; accounts, sessions, articles intact
  • Monthly restore drill scheduled; restore runbook written in DEPLOYMENT.md
Gate: restore succeeds elsewhere with the separate key; failure alert works; RPO/RTO are numbers.
Evidence: off-host backup file, restore log, alert test, key location.
Note: this is a rehearsal on staging; M3 repeats it on production.
M3Production Foundation1–2 days
Goal

Go live on the real domain in production mode before any client touches it.

Checkpoints
  • DNS + TLS for huuk.teenueng.com
  • Production env: DEMO_MODE empty, AUTH_REQUIRED=true, SWAGGER_UI empty
  • New secrets for production, not reused from staging
  • Smoke on the live domain using a dedicated smoke account; delete test content afterward and disable the account
  • Verify security headers, HSTS, CSP on live responses
  • Monitoring (uptime, disk, backup failure) pointed at production, alert tested
  • Backup pointed at production data; restore the production snapshot onto another machine (never over prod)
  • Rollback/update plan and an incident-communication plan for clients
  • Short client onboarding guide (login, change password, publish)
Gate: live domain in production mode; smoke passes; backup and monitoring on prod; rollback plan ready.
Evidence: https://huuk.teenueng.com, smoke output, restore from a prod snapshot.
M4Client Pilot1–2 weeks
Goal

One real client uses Huuk unaided on production. This is the main Definition of Done.

Checkpoints
  • Legal: ToS, privacy policy (PDPA, covering OAuth tokens), pilot agreement (states free vs. paid)
  • Process to export or delete a client's data on request
  • Owner creates the client account (role Client, temporary password); client changes it immediately
  • Password reset/recovery flow verified before handover
  • Client sees only Content / Studio (no planner or settings)
  • Client writes → previews → publishes/schedules → shares /#/read/{slug}
  • Measure against the criteria from the Decision Log (e.g. ≥ 3 articles in 1–2 weeks)
  • Collect feedback, rank bugs, set up a support channel
Gate: client publishes unaided to the agreed criteria; no blocker bugs (as defined in the Decision Log).
Evidence: links to client-published articles, feedback summary, measured criteria.
Note: I'm not a lawyer; have the legal documents reviewed by a professional.
M5OAuth Live, 1 providerafter M3 · parallel to M4
Goal

Connect one real provider end to end, using the production domain.

Checkpoints
  • Create the OAuth app; set META_* / GOOGLE_* / TIKTOK_* in env
  • Register the redirect URI PUBLIC_URL/api/oauth/{platform}/callback for the production domain
  • Set PUBLIC_URL, FRONTEND_URL, CORS_ORIGINS to match
  • Login → callback lands on /#/profile?oauth=...&status=ok
  • Tokens are encrypted (chacha20poly1305) and absent from logs
  • Token refresh verified over time. Check the provider's current rules, since some testing modes expire refresh tokens quickly
  • Revoke, then reconnect
Gate: a real user links an account, sees platform data, and refresh works.
Evidence: /#/profile?oauth=ok screen, refresh test result.
M6Pricing & Invoice1 day + payment wait
Goal

Confirm pricing using pilot feedback and send the first invoice. Starts after the first week of the pilot.

Checkpoints
  • Choose pricing model (per seat / per workspace / per content volume)
  • Set ALLOW_REGISTRATION to match (self-serve vs. invite-only)
  • Payment channel, quote and invoice ready
  • Trial and renewal terms
  • Announce price and send the pilot client's invoice
Gate: price announced and invoice sent.
Follow-up metric (does not block closing): payment received within 30 days. Assign an owner and a review date in the backlog.
M7Portfolio & Handoff1 day
Goal

Close out so the project can be maintained without relying on memory.

Checkpoints
  • Add Huuk to 02_Website/portfolio (link, description, preview image)
  • Update Docs/00_STATUS.md and MASTER_INDEX.md
  • Update CHANGELOG and tag the release
  • Final client/admin guide (onboarding, backup/restore, update, password reset)
  • Close P0 items per the agreed definition; open the next backlog
Gate: portfolio link opens; docs complete; P0 = 0.
Evidence: portfolio link, release tag.

06

Definition of Done

The project is complete when all of these are true at once:

  1. A real client logs in and creates/sends articles via /#/studio unaided, to the agreed criteria
  2. Articles are published and publicly readable at /#/read/{slug}
  3. At least one real OAuth provider is connected end to end, with token refresh verified
  4. Daily backups run and a restore succeeded on another machine with a separately stored key, with failure alerts
  5. Live on huuk.teenueng.com in production mode with TLS, monitoring and rollback
  6. ToS and privacy policy (PDPA) are ready, and password reset works
  7. Price announced and first invoice sent (payment tracked as a follow-up)
  8. Docs updated (STATUS, DEPLOYMENT runbook, MASTER_INDEX, CHANGELOG) and Huuk is in the portfolio
