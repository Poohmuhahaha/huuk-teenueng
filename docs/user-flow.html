User Flows — มี logic

ชุด flow ที่แสดง เงื่อนไข (gate/decision), การพึ่งพากันระหว่าง feature, branch ตาม persona/role และ error path — ดึงจาก code จริง (`server/src`, `app/src`) ไม่ใช่แค่เอา user story มาเรียงตาม epic

01

Global gate & persona routing

  • เปิดแอป → restore() อ่าน token → ไม่มี/หมดอายุ → clearSession(); มี → GET /api/auth/me
  • boot ยังไม่พร้อม → โชว์ loader; พร้อม → แยก public route vs protected
  • protected + authRequired + ยังไม่ล็อกอิน → /login (ผิดเกิน 10 ครั้ง/15 นาที → 429, รหัสผิด → 401 แบบไม่เปิดเผยอีเมล)
  • ยังไม่มี workspace → /welcome สร้าง workspace แรก
  • role = Client → deck เหลือ Content Studio; อื่น ๆ → AppShell (การ์ดตาม can())
02

Feature dependencies — จุดที่ feature ต้องพึ่งกัน

  • Workspace เป็น scope ของทุกข้อมูล (สลับ workspace = เปลี่ยนทั้งชุด)
  • Brand → applyBrandTheme() เปลี่ยนธีมทั้งเว็บ + หน้า public read (ฟีเจอร์เดียวกระทบทั้งระบบ)
  • Platform connection (OAuth) เป็น prerequisite ของ Live mirror, Import metrics และ Meta Ads — ต้อง connected + มี token
  • Ideas → promote สร้าง Post; Posts เป็น master ที่ป้อน derived views (Calendar/Dashboard/Feed/Performance)
  • Campaigns link content; Content Studio เผยแพร่ → Public read
  • Settings/Roles → require_perm เป็นด่านของทุก write (เส้นประ)
03

Core content lifecycle (end-to-end)

  • Idea → promote → Post (planner) → แก้ฟิลด์; lock: ถ้า lockedBy เป็นคนอื่น → เซฟ/ลบ → 409
  • บันทึก post → invalidate posts + metrics → derived views อัปเดตอัตโนมัติ
  • Studio: autosave ทุก 1.5s พร้อม version; version ไม่ตรง → 409 → Reload latest / Keep mine
  • publish/schedule → promote_due_scheduled (lazy) → ปรากฏที่ public read; draft/review/scheduled มองไม่เห็น
04

Connections → data features

  • Connection มี state: disconnected → connected → error; hasToken=false = ต้อง reconnect
  • OAuth: state 128-bit TTL 10 นาที single-use; บัญชีเดียว = apply ทันที, หลายบัญชี = เลือก Page (pending TTL 10 นาที)
  • Sync ต้อง status=connected (ไม่งั้น 400); Meta ดึง Graph นอก lock แล้วเขียนกลับใต้ lock
  • Ads เป็น read-only จนเปิด ads_manage; ทุก mutation ต้องผ่าน manage_context + เขียน AdsAudit
05

Permission decision (FE + BE)

  • FE: usePermission().can(perm) → ถ้าไม่มีสิทธิ์ disable/hide ปุ่ม (แค่ UX)
  • BE: require_read_auth (GET ที่ไม่ public) → require_perm → admin token? → demo? → valid session? → role มี perm?
  • ผลลัพธ์: 401 (ไม่มี/ผิด session) · 403 (ไม่มีสิทธิ์) · bypass ด้วย X-Admin-Token
06

Admin / setup & client onboarding

  • Owner แก้ setup/options (setup.write), role matrix + users (users.manage) — permission ต้องอยู่ใน KNOWN_PERMISSIONS ไม่งั้น 400
  • แก้ role → FE invalidate → can() คำนวณใหม่ทันที
  • Onboard ลูกค้า: สร้าง account + Argon2id + directory role → cp-‹12hex› แสดงครั้งเดียว → ลูกค้าเห็นเฉพาะ Content Studio
  • authRequired เปิด = บังคับล็อกอิน; ปิด = demo (dev เท่านั้น)
07
